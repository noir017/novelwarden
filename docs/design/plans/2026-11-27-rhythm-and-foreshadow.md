# 治「剧情平」与伏笔：看点分类型、节奏体检、伏笔加「强化」、回收带种子

> 2026-11-27。**在 main 上直接开发**。起因：调研了 11 个开源 AI 写小说项目（报告不在仓库里），它们治「平」靠的是细纲里的看点必填 + 跨章数节奏，不靠写正文的提示词；伏笔都是账本 + 状态 + 计划回收章 + 写作时分档注入。对照下来，我们伏笔这侧与主流持平，缺两样：跨章的「平」检测、伏笔的「推进」事件；另外回收那一章写正文时只给伏笔名字。盲读实验之后作者说文笔不是瓶颈，下一步看规划层，这一份只动规划层。

## 原则

- **调用 +0**，不加细纲小节。看点的类型写在「看点」每一行行首；强化是叙事线里多一种事件。
- **节奏只摆给作者看**，不拿章龄逼模型：inkos 早期为「伏笔只加不收」加了排期、催收，到 v1.8 又全删了，改成方法论（「不要因为章龄制造紧迫感」）。节奏提醒同叙事线提醒：零调用、不拦人、不进主按钮（第 20 条）。
- 状态现算、不落盘（第 18 条）；认不出的行照旧当看点、不进统计（第 1 条）。

## 一期：治「平」

### 1. 看点分类型

- 「看点」每条写成 `- 类型：具体的那一下`。排细纲（`context/prompts.ts` 的 `blueprintFormat`）与同步（`features/summarizePrompt.ts`）两份提示词同一句。
- 认类型在 `model/rhythm.ts` 的 `highlightTypeOf`：冒号前是 8 种之一（或几个别名：高光对决 → 对决、悬念 / 章末钩子 → 钩子、揭秘真相 → 揭秘……）才算；别的照旧是看点，只是不进统计。
- 排细纲的「商业网文节奏设计原则」补两句：同一类看点不连用 3 章以上；关键事件里至少一条写清主角的选择和代价，或局势翻过来的那一下。前序细纲一览本来就带看点，不另加上下文。

### 2. 节奏体检（`model/rhythm.ts`，纯函数）

逐章读「看点」与「状态变更」两节，报四种：

| 种类 | 条件 | 说法 |
|---|---|---|
| `dry` | 连续 ≥5 章有类型、都只有钩子 | 第 12–17 章只有钩子，没有兑现 |
| `repeat` | 同一种兑现连着 ≥3 章都有 | 第 20–22 章连着 3 章都是打脸 |
| `noHook` | 连续 ≥2 章有类型、都没有钩子 | 第 8–9 章章末都没有钩子 |
| `static` | 「状态变更」写的是「无」 | 第 30 章状态变更是「无」，这一章什么都没变 |

- 一章「有类型」= 看点里至少一条认得出类型。没类型的章（老书、作者手写的）切断连续，不报，免得误报。章号断开也切断。
- 同步过的章（细纲有 `sourceHash`、正文还在）按正文算；没同步的按计划算。一段里有计划章的，说法后面注「（含计划）」。
- 不拿「完结」那一章另算：最后一章没钩子也照报，作者自己判断。

### 3. 显示

- **工程页「叙事线」页签**：最上面一组 ⚠ 行（与「还没判」同一个样子），一处一行，最多 5 行，再多的并成一句「等 N 处」。
- **叙事线总览**：表头下面一行「看点」，每章一格写这一章第一种兑现的类型的头一个字（只有钩子的写「钩」，没类型的空着），落在问题段里的格子标黄；悬停看这一章的全部看点。
- **写前检查**：`ThreadWatch` 多带一份 `rhythm`（全书的问题段），`threadRemindersFor` 把碰到要写的哪一章的报成 `rhythm` 一类，说法另起一句「节奏提醒：……」。对话页卡片、工作台、批量写章弹窗走现有的那几条路，不另开。
- **外部 agent**：`stateBrief` 多一行，最多点名 5 处。

## 二期：伏笔

### 1. 加「强化」事件

- 伏笔事件：埋 / 收 / 弃 → 埋 / 强化 / 收 / 弃（`model/threadFile.ts`）。别名只收「加深」「reinforce」；「推进」仍是线的事件，`推进〈伏笔名〉` 不改认法。
- 强化不改状态（还是「已埋」）。`foreshadowingOf` 多算两样：强化了几次、最近第几章碰过（埋或强化里晚的）。
- 同步认事件（`features/threadsPrompt.ts` 的 `THREAD_FIND_SYSTEM`）加强化的定义：正文给了新线索、加深了疑点、让读者离真相更近一步，但没揭开；只提了一句名字、角色回想一下不算。照旧要证据原句。还没埋的伏笔不能强化（同「没埋就收」，丢掉）。
- 排细纲的叙事线合同允许排「强化」（可选，不强制）。
- 显示：总览伏笔格子多一种记号；工程页、总览伏笔的提示写「第 3 章埋 · 强化 2 次 · 最近第 21 章」。

### 2. 回收那一章带上种子

- 写正文时，标着「本章计划收」「已过第 N 章，还没收」的伏笔，从只给名字改成：名字（说法）——说明；埋下：「证据原句」；强化：「……」。没到回收章的照旧只给名字和「第 b 章前不要揭开」。
- 拆细纲时标着「本批要收」「本章要收」的同样带说明与证据原句。
- 证据最多带 3 句（埋 1 句 + 最近的强化 2 句），每句沿用事件证据的 80 字上限；整层照旧受这一层的总字数管，放不下的在明细里写原因（第 2 条）。

## 不做

- 每章打冲突强度分：模型打分噪声大，先用看点类型代替。
- 伏笔逾期自动重排后续细纲：第 4 条。
- 把「埋了很久没动」推给模型。
- 句子层的细节、去 AI 味。
- 论文里的对抗式悬念规划：多花调用。
- 老书补类型、补强化：要调模型；重新同步过的章自然就有。
